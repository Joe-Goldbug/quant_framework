## 2. 为什么这 5 道门禁过不去 (代数)

平台指标恒等式 (本轮在 30 个槽位上逐位复算, 全部吻合):

```
margin_bps = returns / turnover × 20
fitness    = sharpe × sqrt( returns / max(turnover, 0.125) )
```

两者联立, 当 `turnover ≥ 12.5%` 时母项被 0.125 保底, 得到**精确替换式**:

```
fitness = sharpe × sqrt( margin_bps / 20 )
```

于是 **`sharpe² × margin_bps` 是一个可测量的数据集常数**:

| | 实测值 |
|---|---|
| 224 个 alpha 的 `Sharpe² × Margin` 最大值 | **~7.9** (E56Rzr2L: 0.97²×8.37) |
| 由此推出的 Fitness 上限 | `sqrt(7.9/20)` = **0.63** (实测最大 0.63) |

这就解释了为什么 224 个槽位的 Fitness 全部挤在 0.6 附近 —— **Fitness 不是没优化到, 是被这个乘积锁死**。

现在把任务书的门禁代进这个恒等式:

| 门禁 | 代数要求 | 实测最好 | 缺口 |
|---|---|---|---|
| Fit ≥ 1.05 | `Sh² × Mgn ≥ 22.05` | 7.9 | **2.8×** |
| Sh ≥ 1.65 且 Mgn ≥ 15 | `Sh² × Mgn ≥ 40.8` | 7.9 | **5.2×** |
| Mgn ≥ 15bps | `R/TO ≥ 0.75` | 0.422 | **1.78×** |
| **门禁 4 + 门禁 5** | `R ≥ 5.5%` 且 `Mgn ≥ 15` ⟹ `TO ≤ 7.33%` ⟹ `R ≥ 4.0×Mgn/20` … | — | **矛盾** |

最后一行是关键: 门禁 5 要求 Returns ≥ 5.5%, 门禁 4 要求 Margin ≥ 15bps。
由 `Mgn = R/TO×20` 得 `TO = R×20/Mgn ≤ 5.5×20/15 = **7.33%**`。
而 R/TO 天花板 0.422 意味着在 TO=7.33% 时 `R ≤ 0.422×7.33% = **3.09%** < 5.5%。
**两道门在同一个等式下互斥**, 与表达式写法无关。

顺带: 门禁 1 + 门禁 4 若同时成立, 会**自动蕴含**门禁 2
(`1.65×sqrt(15/20) = 1.43 ≥ 1.05`) —— 所以真正卡死的是 Margin 那一道。

## 3. 全战役 224 槽的门禁分布

```
Sharpe ≥ 1.58 且 Margin ≥ 10bps  : 0 / 224
Fitness ≥ 1.00                    : 0 / 224
Cluster ≥ 1.58                    : 1 / 224 (d5W1lzjx, 但 TO 73% / Fit 0.41)
Margin ≥ 10bps                    : 1 / 224 (w15_tvr05_d0, 但 Sh 0.66)
```

单指标与多指标是**严格互斥**的: 拿到 Sharpe 的必然丢 Margin, 拿到 Margin 的必然丢 Sharpe,
而 `Sh²×Mgn` 恒定 ⇒ 任何移动都只是沿前沿滑动, 不抬高度。

## 5. 下次真正能突破的方向 (基于本轮证据)

224 槽唯一没被证伪的杠杆是**「换一类信息」**。`oth566` 全部 51 个字段都是同一套图像模型对
未来 1–5 日收益的**输出**, 彼此高度同源 —— 这就是 `Sh²×Mgn` 常数存在的物理原因:
同一份信息无论怎么线性重组, 单位换手收益都跑不出 0.42。

需要的是一个**与订单簿形态预测正交**的腿 (真正的盈利修正 / 基本面意外 / 期权隐含波动率偏斜),
把 `R/TO` 从 0.42 抬到 0.75 —— 这需要 +78% 的单位换手收益, 是参数层面做不到的量级。
